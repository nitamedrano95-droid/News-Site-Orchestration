## Schema de cada DB test

Cada DB tiene 5 tablas (mínimo viable para el editor + asignación a sitio):

  · `ARTICULOS_CMS` (donde escribe el editor HUB)
  · `ARTICULOS_SITIO_<SITIO>` (1 tabla por DB, nombre del sitio en MAYÚSCULAS)
  · `CATEGORIAS` (9 categorías seed)
  · `SITIOS` (registro del sitio muestra)
  · `USUARIOS` (admin test)

`ARTICULOS_CMS` incluye todas las columnas que el editor HUB +
SeoPanel necesitan: SEO (META_TITLE, META_DESCRIPTION,
FOCUS_KEYWORD, TAGS, READING_SCORE, READING_ANALYSIS),
workflow (STATE_HISTORY, ESTADO), asignación (SITIOS_DESTINO),
FB integration (FB_PUBLICADO, FB_FECHA, FB_SITIOS_PUBLICADOS).

## Webhook de publicación

Variable en cada `wrangler.toml`:
```
ARTICLE_PUBLISH_WEBHOOK = "TBD_WEBHOOK_URL"
```

El Worker hace POST al webhook cuando:
- Se crea un artículo con `estado = "PUBLICADO"`
- Se actualiza un artículo pasando de no-PUBLICADO a PUBLICADO

Payload:
```json
{
  "event": "article_published",
  "source": "cms-{name}-test",
  "article_id": "uuid",
  "slug": "...",
  "title": "...",
  "sitios_destino": "bitacoraurbana",
  "timestamp": "ISO 8601"
}
```

**Por configurar:** el usuario debe cambiar `TBD_WEBHOOK_URL` por la
URL real del workflow n8n. Ver `docs/guides/n8n-fb-publicado-sync.md`.

## Limitaciones conocidas

1. **Worker version**: Hub test corre con wrangler 3.114.17 (warning
   "out of date"). Funciona pero conviene actualizar a 4.x.

2. **SQL grande con wrangler 4.97**: SQLs de ~2KB con muchas
   columnas (>14) hacen que wrangler devuelva stderr pero no
   ejecute. Solución aplicada: INSERT con 14 columnas, UPDATE
   para SEO fields. Documentado en `seed/seed-cms-test.py`.

3. **READING_ANALYSIS en nuevos4-test**: 0/5 artículos lo tienen
   por el bug de wrangler con SQL grande. Workaround: el SeoPanel
   calcula el score en vivo en el cliente, así que no afecta UX.

4. **Hub test tiene UI propia** ✅: `nexopress-hub-ui-test.pages.dev`
   buildeada contra el Hub test. Pasos:
   - `cp -r nexopress-hub-ui nexopress-hub-ui-test`
   - `.env.production` con `VITE_API_BASE=https://nexopress-hub-test.chispakimnueve.workers.dev/api`
   - `npm run build` (785 KB JS / 12.8 KB CSS)
   - `wrangler pages project create nexopress-hub-ui-test`
   - `wrangler pages deploy dist --project-name=nexopress-hub-ui-test --commit-dirty=true`

5. **Webhook `TBD_WEBHOOK_URL`**: no se invoca, solo placeholder.
   Cualquier POST a `TBD_WEBHOOK_URL` fallaría hasta que se cambie.

## Cómo seguir

1. **Cambiar el webhook real**: editar `ARTICLE_PUBLISH_WEBHOOK`
   en cada `cms-test/workers/cms-*-test/wrangler.toml`,
   redeployar.

2. **Probar el editor HUB contra test** ✅: ir a
   https://nexopress-hub-ui-test.pages.dev y loguear con
   `admin@test.nexopress.io` / `test1234`.

3. **Smoke test del editor**: login con `admin@test.nexopress.io` /
   `test1234`, crear artículo, ver que se guarda en
   `ARTICULOS_CMS` y se asigna a `ARTICULOS_SITIO_<sitio>`.

4. **Probar el webhook**: cambiar la URL a un `https://webhook.site/`
   temporal, crear un artículo PUBLISHADO desde el editor, ver
   que llegue el POST.

5. **Limpieza al terminar**: si el test ya cumplió su propósito,
   las 5 D1 + 7 KVs + 6 Workers se pueden borrar con
   `wrangler d1 delete <name>` y `wrangler delete`.
